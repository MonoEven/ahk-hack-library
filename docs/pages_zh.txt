[b]1. 目标与方法[/b]

目标是把 [c]AutoHotkey64.exe[/c] 当作活体解释器分析，并提取足够多的结构来实现表达式求值、内存脚本加载、远程 Hook 和在线函数 Trace。方法是可重复的循环：先读源码找出候选字段，再检查进程内存确认真实偏移，把稳定逻辑编码成位置无关机器码，最后用结构不变量验证每个结果。

本页记录的就是这个循环。

[b]2. PE 解析与节区映射[/b]

每个 x64 AutoHotkey v2 可执行文件都以 [c]MZ[/c] DOS 头开始。PE 签名位于 [c]e_lfanew[/c] 指向的偏移，可选头使用 PE32+ 魔数 [c]0x20B[/c]。节表紧随可选头。

[codebox=autohotkey file=pe-map]
peOff   := NumGet(base, 0x3C, "UInt")
numSec  := NumGet(base + peOff + 6, "UShort")
optSize := NumGet(base + peOff + 20, "UShort")
secTab  := base + peOff + 24 + optSize

loop numSec {
    off := (A_Index - 1) * 40
    name := StrGet(hdr.Ptr + off, 8, "UTF-8")
    vsize := NumGet(hdr + off + 8, "UInt")
    va := NumGet(hdr + off + 12, "UInt")
    rawSize := NumGet(hdr + off + 16, "UInt")
}
[/codebox]

扫描器把每个节区保存为 [c]{rva, size, ptr}[/c]，并按名称分类。三个节区最重要：

| 节区 | 作用 | 不变量 |
| --- | --- | --- |
| [c].text[/c] | 可执行代码 | 函数指针必须落在这里 |
| [c].rdata[/c] | 只读字符串 | UTF-16 名字通常在这里 |
| [c].data[/c] | 可写全局量 | 解释器表在这里 |

对于加壳构建，节名不可靠。扫描器会退回到基于内容的分类：非 [c].rsrc[/c] 的代码样节区当作可执行节区，可读的非执行节区当作数据/字符串存储。

[b]3. 解释器表发现[/b]

解释器在镜像中维护三张表。它们的 x64 记录步长是稳定的：

| 表 | 内容 | 记录步长 |
| --- | --- | --- |
| [c]g_BIF[/c] | 脚本可见内置函数，如 [c]Abs[/c]、[c]Sin[/c] | [c]0x20[/c] |
| [c]sMdFunc[/c] | 带类型签名的原生函数，如 [c]MsgBox[/c] | [c]0x28[/c] |
| [c]g_BIV_A[/c] | 以 [c]A_[/c] 开头的内置变量 | [c]0x18[/c] |

扫描器不硬编码地址。它按指针对齐槽位扫描，只有同时满足以下条件才接受记录：

- 第一个 qword 解析为可打印 UTF-16 字符串；
- 第二个 qword 落在 [c].text[/c]；
- 相邻记录按名字排序；
- 存在 [c]Abs[/c]、[c]BlockInput[/c] 或 [c]AhkPath[/c] 等锚点。

最长的合法连续区成为目标表。同一算法以 x64 机器码运行，因此扫描速度与逻辑不依赖 AHK 版本。

[b]4. 源码到内存的验证[/b]

源码提供名字与意图，不提供最终偏移。编译器、构建选项和调试器字段都会移动成员。因此流程先用源码形成假设，再用内存确认。

对于 [c]script.h[/c] 中的 [c]UserFunc[/c]，源码声明了：

[codebox=cpp file=userfunc-source]
class UserFunc : public Func
{
public:
    int mInstances = 0;
    Line *mJumpToLine = nullptr;
    FuncParam *mParam = nullptr;
    Object *mClass = nullptr;
    ...
    VarList mVars {};
    VarList mStaticVars {};
};
[/codebox]

内存探针在两个代表性构建上确认了实际 x64 布局：

| 字段 | v2.1-alpha.30 | v2.0.26 |
| --- | --- | --- |
| [c]mName[/c] | [c]0x28[/c] | [c]0x20[/c] |
| [c]mJumpToLine[/c] | [c]0x48[/c] | [c]0x40[/c] |
| [c]mParam[/c] | [c]0x50[/c] | [c]0x48[/c] |
| [c]mVars[/c] | [c]0x80[/c] | [c]0x70[/c] |

偏移不同，所以库在运行时发现它们，不维护版本表。

[b]5. 机器码提取流水线[/b]

稳定扫描器写在 [c]lib/mcode/[/c] 下的 C 源码中。构建使用 clang 生成无 CRT、位置无关的 COFF 对象：

[codebox=text file=clang-build]
clang -c -O2 -target x86_64-pc-windows-msvc -ffreestanding \
  -fno-builtin -fno-stack-protector -fno-unwind-tables \
  -fno-asynchronous-unwind-tables -fno-jump-tables scanner.c
[/codebox]

[c]tools/build_mcode.py[/c] 执行四步检查：

- 从 COFF 对象提取 [c].text[/c]；
- 解码每条重定位记录；
- 只有目标仍在 [c].text[/c] 内的 [c]IMAGE_REL_AMD64_REL32[/c] 才被接受；
- 任何引用逃出代码块的内容都会被拒绝。

最终十六进制字符串嵌入 [c]ahk_hack_single.ahk[/c]。[c]MCode()[/c] 把字符串解码为 [c]Buffer[/c]，修改为可执行保护，并返回给 [c]DllCall[/c]。

[b]6. EvalNative：表达式求值分析[/b]

AutoHotkey 不会直接求值表达式字符串。脚本加载时，[c]Line::ExpressionToPostfix[/c] 把表达式编译成 [c]ExprTokenType[/c] 后缀数组，[c]Line::ExpandExpression[/c] 之后再执行该数组。

[c]EvalNative()[/c] 构造解析器本来会创建的临时 [c]Line[/c] 和 [c]ArgStruct[/c]，然后调用这两个函数。因此它复用了解释器自己的语法与变量解析。

内部定位器机器码发现以下符号：

| 符号 | 来源 | 发现方式 |
| --- | --- | --- |
| [c]ExpressionToPostfix[/c] | 错误串 [c]"Missing operand."[/c] | RIP 相对引用 + prologue 回退 |
| [c]ExpandExpression[/c] | 错误串 [c]"Error evaluating expression."[/c] | RIP 相对引用 + prologue 回退 |
| [c]gScript[/c] | 最频繁的 [c]lea rcx,[rip+disp][/c] 目标 | 频率过滤 |
| [c]FindOrAddVar[/c] | 六参数 prologue | 签名匹配 |
| [c]SYM_INVALID[/c] | 后缀终止符 | 求值器内立即数 |

求值器使用的 token 布局：

| 字段 | 偏移 | 类型 |
| --- | --- | --- |
| value | [c]0x00[/c] | 指针/int64/double 联合 |
| marker/usage | [c]0x08[/c] | 指针或 [c]VarRefUsageType[/c] |
| symbol | [c]0x10[/c] | 32 位 [c]SymbolType[/c] |
| stride | [c]0x18[/c] | 结构总大小 |

[codebox=autohotkey file=evalnative]
#Include ahk_hack_single.ahk
AhkMagic.Init()

MsgBox AhkMagic.EvalNative("1 + 2 * 3")           ; 7
MsgBox AhkMagic.EvalNative("2 * 3.5")             ; 7.0
MsgBox AhkMagic.EvalNative("Abs(-5)")             ; 5
MsgBox AhkMagic.EvalNative("SubStr(`"abc`", 2)")  ; "bc"

myVar := 42
MsgBox AhkMagic.EvalNative("myVar + 1")           ; 43
[/codebox]

[b]7. EvalScript：解析器与内存加载[/b]

表达式求值无法定义函数或类。[c]EvalScript()[/c] 通过内存 [c]TextStream[/c] 把多行文本喂给解释器的 include 管线。

相关管线：

[codebox=cpp file=load-include]
ResultType Script::LoadIncludedFile(TextStream *fp)
{
    int source_file_index = mCurrFileIndex;
    bool blocks_previously_open = mLineParent || mClassObjectCount;
    auto module_previously_open = mCurrentModule;
    bool caller_backcompatmode = mBackCompatMode;
    ...
}
[/codebox]

加载前，库保存并在之后恢复：

- [c]mOpenBlock[/c] / [c]mLineParent[/c]；
- [c]mPendingRelatedLine[/c]；
- [c]mLastParamInitializer[/c]；
- [c]mPendingHotkey[/c]；
- [c]mExprFuncIndex[/c]；
- [c]mNextLineIsFunctionBody[/c]；
- [c]mIgnoreNextBlockBegin[/c]；
- [c]mBackCompatMode[/c]；
- [c]mClassObjectCount[/c]；
- [c]mCurrentModule[/c] 与 [c]mLastModule[/c]。

解析器状态锚点从 [c]LoadIncludedFile[/c] prologue 中读取：

- [c]q[/c]：指向 [c]mOpenBlock[/c]/[c]mLineParent[/c] 的偏移；
- [c]d[/c]：指向 [c]mClassObjectCount[/c] 的偏移。

[c]TextStream[/c] 同时填充两种可能的 [c]mData[/c] 区域，因此同一对象可用于 2.0 与 2.1 布局。

[b]8. 远程内省[/b]

[c]AttachRemote(pid)[/c] 使用 [c]OpenProcess[/c] 打开目标，读取 PE 镜像，扫描解释器表，并返回 hook map。

远程求值注入线程 stub、定位器和求值器 blob：

| 步骤 | 操作 |
| --- | --- |
| 1 | 用 [c]VirtualAllocEx[/c] 分配 scratch 块 |
| 2 | 写入 stub、定位器、求值器、表达式、输出缓冲 |
| 3 | 用 [c]CreateRemoteThread[/c] 创建远程线程 |
| 4 | 等待并读取结果缓冲 |
| 5 | 释放 scratch 块 |

[c]RemoteEvalScript()[/c] 使用目标自己的 [c]LoadIncludedFile[/c] 与 [c]PreparseExpressions[/c]。注入线程会在 preparse 前设置 [c]g->CurrentFunc[/c]，因此 class 方法与 [c]Super[/c] 能正确解析。

[codebox=autohotkey file=remote-eval]
hook := AhkMagic.AttachRemote(pid)
MsgBox AhkMagic.RemoteEval(hook, "1 + 2 * 3")     ; 7

script := "
(
rhkAdd(a, b) {
    return a + b
}
rhkAdd(1, 2)
)"
MsgBox AhkMagic.RemoteEvalScript(hook, script)    ; 3
[/codebox]

函数体替换交换 [c]mJumpToLine[/c]：

[codebox=autohotkey file=remote-replace]
AhkMagic.RemoteEvalScript(hook, "
(
NewA() {
    return 42
}
NewA()
)")
AhkMagic.RemoteReplaceFuncBody(hook, "A", "NewA")
Send("{F9}")
[/codebox]

目标开始输出 [c]A()=42[/c]，原始输出为 [c]A()=1[/c]。

[b]9. 动态偏移发现[/b]

远程布局扫描器从存活内存推导 [c]mFuncs[/c]、[c]mFuncsCount[/c]、函数名字段与 [c]mJumpToLine[/c]：

- 候选 array/count 对通过读取每个 [c]Func[/c] 指针验证；
- [c]mName[/c] 是指向合法标识符字符串的指针；
- [c]mJumpToLine[/c] 指向包含回指所属 [c]Func[/c] 的 [c]Line[/c]；
- 回引用槽位在普通函数之间保持一致。

结构验证器随后发现：

| 结构 | 验证字段 |
| --- | --- |
| [c]Line[/c] | action、argc、arg 指针、attribute、next |
| [c]ArgStruct[/c] | is_expression、postfix 指针、deref 指针 |
| [c]ExprTokenType[/c] | stride、symbol 偏移、usage 偏移、value 偏移 |
| [c]DerefType[/c] | marker、var、type、length |

Token 数组通过走到 [c]SYM_INVALID[/c] 并在终止符前要求一个 [c]SYM_VAR[/c] token 来验证。[c]DerefType[/c] 从运行进程中已有的 [c]ArgStruct.deref[/c] 数组读取。

[b]10. TraceFunction：基于克隆的 Trace[/b]

函数 Trace 比函数替换更难。最初实现重命名目标函数并注入 wrapper，结果失败，因为：

- 函数名同时存在于 [c]Func.mName[/c] 与全局 [c]Var.mName[/c]；
- [c]mFuncs[/c] 与 [c]VarList[/c] 是排序数组；
- 只改一边会破坏二分查找；
- 只替换函数体不会重新绑定参数 [c]Var[/c] 对象。

稳定修复来自阅读 [c]UserFunc::Call[/c]：

[codebox=cpp file=userfunc-call]
bool UserFunc::Call(ResultToken &aResultToken, ExprTokenType *aParam[], int aParamCount)
{
    ...
    for (j = 0; j < mParamCount; ++j)
    {
        FuncParam &this_formal_param = mParam[j];
        ...
    }
}
[/codebox]

调用路径通过 [c]mParam[i].var[/c] 写入参数。因此两个函数对象可以共享同一组参数 [c]Var[/c]，两个函数体都能看到相同值。

最终设计：

- 克隆 [c]UserFunc[/c] 对象；
- 为克隆体创建 [c]VAR_CONSTANT[/c] 全局别名；
- 注入调用克隆体的 wrapper；
- 把 wrapper 的参数 [c]Var[/c] 别名回原函数参数；
- 替换原函数体指针；
- Untrace 时恢复原 [c]mJumpToLine[/c]。

Wrapper 写入目标端全局字符串，因此 [c]RemoteEval[/c] 可以读取 Trace 日志，而不依赖求值线程内的文件 I/O。

[color=#BF4000][b]11.1 回归覆盖：错误捕获[/b][/color]

GUI 会把每个 [c]AhkLiveResult[/c] 转成可见的日志行。[c]OnError()[/c] 同时把异常字段写入 GUI 日志和 [c]%TEMP%\ahk_live_gui_error.log[/c]；[c]SafeStr()[/c] 序列化 Map/Array 值，避免第二个错误再次弄崩日志器。Watch 与观测错误会作为 [c]Error[/c] 对象转发给回调。[c]--shot <pid> <tab>[/c] 会选中指定页签并写就绪标记，供完整窗口截图自动化使用。

[codebox=autohotkey file=error-capture]
AhkLive_OnError(e, exitCode := 0) {
    msg := "ERR " e.What " | " e.Message
        . " | " e.File ":" e.Line
    FileAppend(msg "`n", A_Temp "\ahk_live_gui_error.log")
    return true
}

OnError(AhkLive_OnError)
[/codebox]

回归测试 [c]tests\ahk_live_regression.ahk[/c] 覆盖构建 GUI 时发现的三类失败：

- [c]EvalScript[/c] 之后执行 [c]TraceFunction[/c]，要求缓存 [c]script_layout[/c] 从 [c]script_loc[/c] 回填 [c]find_var[/c]；
- 快照表达式在括号内含逗号，不能被当成配置分隔符拆分；
- 重复的顶层函数名，必须在 [c]LoadIncludedFile[/c] 执行前拒绝：

[codebox=autohotkey file=duplicate-preflight]
for name in AhkMagic._DeclaredFunctionNames(text) {
    if AhkMagic._RemoteFindUserFuncs(h, layout, name).Length
        throw Error("function name already exists in target: " name, -1)
}
[/codebox]

新回归测试已在 [c]2.1-alpha.30[/c] 与 [c]2.0.26[/c] 通过。19 运行时九项矩阵仍然是完整兼容门槛。

[b]12. 安全与边界[/b]

这个库会分配可执行内存、执行机器码，并写入当前或目标进程的解释器内存。它不具备沙箱隔离。

规则：

- 只附加自己拥有的进程；
- 反复实验使用一次性目标；
- 补丁用 [c]finally[/c] 或 [c]AhkLivePatchSession.Rollback()[/c] 恢复；
- 永远不要 eval 不可信输入；
- 定位失败应视为错误，不猜测偏移。

加壳或恶意构建可能改节名或删字符串。内容分类扫描可以处理常见加壳器，但恶意构建仍可能绕过发现。
